# Documentazione di test

Qui metto come scrivo la documentazione di test, usando [SauceDemo](https://www.saucedemo.com/) come applicazione di esempio. Fa da accompagnamento ai test automatici di [selenium-testng-saucedemo](https://github.com/raffaelefarro/selenium-testng-saucedemo).

| File | Cos'è |
|---|---|
| [test-plan.md](test-plan.md) | Piano di test: cosa provo, cosa no, come, con quali dati e quando ho finito |
| [test-cases.md](test-cases.md) | 19 casi di test, con priorità e il collegamento al test automatico quando c'è |
| [bug-reports/](bug-reports/) | Due bug che ho trovato davvero provando il sito con l'utente `problem_user` |
| [bug-report-template.md](bug-report-template.md) | Il modello che uso per segnalare un bug |

Un bug scritto bene si riproduce senza chiedere niente a chi l'ha trovato: passi, risultato ottenuto, risultato atteso e impatto. È la cosa su cui sono più pignolo.

I due bug nascono da un comportamento che il sito di prova ha messo apposta: li ho segnalati lo stesso per mostrare come li scriverei.
